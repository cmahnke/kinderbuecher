# IIIF Sheet Music Extension

This page contains the unofficial IIIF Sheet Music Extension Version 0.1

## Status

This extension is just a proof of concept and will certainly never be a officially recognized extension. The author has no interest to push this forward.

Version 0.1 describes the sheet music additions the pipeline makes to otherwise plain [IIIF Presentation 3](https://iiif.io/api/presentation/3.0/) manifests for scanned music books. The manifests are generated by `scripts/generate_manifest.py`; the referenced notation files by `scripts/generate_tei.py` and `scripts/run_homr.py`. The sheet music format itself is defined by the TEI customization `schema/homr-tei.odd`.

## Demo

Manifests generated with this extension (static files, Presentation 3):

- [Vieilles Chansons et Danses et Rondes](https://static.projektemacher.org/kinderbuecher/post/vieilles-chansons-et-rondes/manifest.json)
- [Deutsche Wiegenlieder](https://static.projektemacher.org/kinderbuecher/post/deutsche-wiegenlieder/manifest.json)

The [kinderbücher viewer](https://projektemacher.org/kinderbuecher/) consumes them: it renders the scans via the IIIF image services, draws the staff overlays from the TEI, and plays the scores.

## Terms

### Linked data context

This extension adds **no new JSON-LD terms**. Every addition is a value or usage profile of an existing Presentation 3 property (`rendering`, its `label`, and standard MIME types), so manifests keep the single standard context:

```json
{
  "@context": "http://iiif.io/api/presentation/3/context.json"
}
```

No extension context is provided or referenced — the terms introduced by the notation side live in the TEI world (see below), not in JSON-LD.

### Canvas `rendering`

A score page's canvas references its notation as **Alternative Representations** (Presentation 3 `rendering`), in this order:

| Format | Label | Description |
| ------ | ----- | ----------- |
| `application/tei+xml` | `TEI (staff regions + embedded MusicXML)` | Per-page TEI document: the detected staff geometry (`<facsimile>/<surface>/<zone type="staff">` in original image pixels), the OMR run information (`<application ident="homr" status="…" confidence="…">`), and the homr MusicXML embedded verbatim |
| `application/vnd.recordare.musicxml+xml` | `MusicXML` | The plain MusicXML file, for download-only consumers |

Requirements:

- Both entries have `type: "Text"`, an `id` (absolute HTTP(S) URI) and a language-mapped `label`.
- The `rendering` property is present only on canvases whose page contains music; pages without notation have neither entry.
- A canvas with both entries had a successful OMR run; the OMR status and confidence are **not** carried as manifest metadata — they live in the TEI header's `<application>` element so they stay next to the staff geometry they describe.
- There are deliberately no staff annotations on the canvases: the manifest stays staff-free, and any IIIF consumer can walk canvas → TEI rendering → `<surface @corresp>` → `<zone>` to recover the regions.

{
  "id": "https://static.projektemacher.org/kinderbuecher/post/vieilles-chansons-et-rondes/page006/canvas",

    }
  ],
  "items": [
    {
      "id": "https://static.projektemacher.org/kinderbuecher/post/vieilles-chansons-et-rondes/page006/annotation-page",
